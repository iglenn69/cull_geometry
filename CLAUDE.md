# CLAUDE.md - Houdini Frustum Culler HDA## Project OverviewThis repository contains a high-performance Houdini Digital Asset (HDA) designed for cross-context camera frustum culling. The asset operates uniformly across standard OBJ/SOP pipelines and Solaris Stage (LOP/USD) contexts, supporting points, primitives, and heavy packed primitive arrays.## Context Definitions & Node Paths- **OBJ/SOP Context:** Standard execution layer. Camera paths resolve natively via standard object paths (e.g., `/obj/cam1`).- **Stage/LOP Context:** Solaris execution layer handling USD Primitives. Camera paths point directly to LOP primitives (e.g., `/stage/unpacked_usd/Camera`).- **HDA Entry Points:** Instantiated either inside a standard SOP Geo network or wrapped inside a LOP `sopmodify` node.## Key HDA Parameters| Parameter Label | Name | Type | Defaults / Options || :--- | :--- | :--- | :--- || **Camera Path** | `camera` | Operator Path | OBJ camera, LOP node, `<lop>/<prim path>`, or bare USD prim path (inside SOP Modify) || **Camera Prim (USD)** | `cam_primpath` | String | Prim used when `camera` is a LOP node; empty = first camera on stage || **Run over Primitives** | `run_over_prims` | Toggle | `0` = Points, `1` = Primitives (Alters VEX bindings) || **Use Connectivity** | `use_connectivity` | Toggle | `1` = keep a whole piece if any element is visible (internal `__cull_class`) || **Input Packed Geo** | `is_packed` | Toggle | `0` = geometry used as-is (never unpacked), `1` = cull whole packed prims via top-level bounds/centroid || **Primitive Test** | `bound_test` | Menu | `0` Centroid, `1` Bounding Box (default; conservative) || **Z Near / Z Far** | `znear` / `zfar` | Float | `0.1` / `1000.0` || **Overscan Margin** | `overscan` | Float | `0.0` (Percentage multiplier padding, e.g., `0.1` for 10%) || **Viewing Range** | `view_range` | Menu | `0` (Current Frame), `1` (Single Frame, `single_frame`), `2` (Frame Range, `frange`) || **Output** | `output_mode` | Menu | `0` Delete Outside, `1` Delete Inside, `2` Group Only (SOP only) || **Fully Culled Prims** | `usd_cull_method` | Menu | LOP asset only: `0` Deactivate, `1` Make Invisible |## Critical Implementation Rules### 1. Matrix & Coordinate Constraints- **Do not use native VEX `toNDC()`:** It fails completely when evaluating raw USD stage properties or paths starting with `/stage`. Always rely on the manual mathematical projection tracking exposed by the internal Python/VEX resolver bridge.- **Camera Vector Orientation:** In Houdini's native viewing space, cameras look down the **negative Z axis** (`-Z`). Factor this into clipping depth conditionals (`float depth = -cam_space_pos.z;`).- **Transformation Order:** Maintain row-major order evaluation for VEX matrix vector multiplication: `vector_cam = vector_world * m_viewproj;`.### 2. Geometry & Optimization Safeguards- **Packed Geometry Performance:** If `is_packed` is checked, do not unpack deep underlying primitive sets unless explicitly requested. Run your calculations purely across top-level instance centroid points to maintain real-time cooking frames.- **Group Management Consistency:** The culling engine must output culling results to a point/primitive group named `cull_candidates` (written as `i@group_cull_candidates`) instead of executing a destructive `removepoint()` or `removeprim()` statement inline. This allows artists downstream option logic to blast or split.- **Type Safety & Casting:** Always explicitly declare types when parsing geometry arrays or detail parameters coming from the Python evaluation node (e.g., `matrix m_viewproj = getdetailattrib(0, "cam_matrix");`).### 3. VEX Coding Conventions- Declare all working primitive structures using explicit type prefixes (`vector`, `matrix`, `int`, `float`). Do not use untyped implicit assignments.- Split multi-stage equations across readable single rows instead of nested complex inline groupings.- Heavily annotate logic parsing time-range cache accumulation configurations (`view_range == 2`).\n

## Implementation Notes
- Python (`camera_data`) bakes 6 world-space frustum planes per evaluated frame into `f[]@cam_planes` (plus `cam_matrix` = world->clip for the first frame). VEX tests `dot(n, P) + d >= 0`; boxes use the positive-vertex test. This is the same projection as `P * m_viewproj` and is what allows bounding-box tests.
- Geometry SOP space is converted to world via the containing OBJ node's `worldTransformAtTime` (identity inside LOPs).
- USD cameras are evaluated through the internal `cam_import/lop_camera` (lopimportcam). Reading the composed stage directly is NOT enough: LOP-authored animation only carries a time sample for the current frame, which breaks Frame Range mode.
- SOP Modify only overlays edits, so the LOP asset uses a Python LOP (`remove_culled_prims`) to deactivate/hide prims whose geometry was fully removed, and enables SOP Modify topology handling (`animated` for Current Frame, `static` otherwise) for partially culled meshes.
- `setup_claude_md.py` regenerates an older version of this file; update it before running it.
